# GitHub Pages 入门

GitHub Pages 是 GitHub 提供的免费静态网站托管。这篇笔记记录它的核心规则。

## 一个仓库，一个站点

这是最容易记混的地方：

| 说法 | 是否正确 | 说明 |
| --- | --- | --- |
| 一个仓库只能一个站点 | ✅ | 每个仓库对应一个独立的发布单元 |
| 一个账号只能一个站点 | ❌ | 站点数量 = 你的仓库数量，不限 |
| 只能托管在 `.github.io` 仓库 | ❌ | 每个仓库都能各自开启 |

## 两类站点

| 类型 | 仓库名 | 访问地址 | 数量 |
| --- | --- | --- | --- |
| 用户站点 | `encounter888.github.io` | `https://encounter888.github.io/` | 每账号仅 1 个 |
| 项目站点 | 任意，如 `docs` | `https://encounter888.github.io/docs/` | 不限 |

本项目就是**项目站点**，挂在用户站点的 `/docs/` 路径下。两者互不干扰，可以同时存在。

## 能做什么，不能做什么

Pages 只负责发送静态文件，**服务器端不执行任何代码**。

**可以：**

- HTML / CSS / JS 静态文件
- React / Vue 打包后的产物
- 图片、字体、PDF
- 在浏览器里调用外部 API

**不可以：**

- 后端代码（PHP / Python / Node 服务）
- 直接读写数据库
- 服务端定时任务
- 隐藏 API 密钥（所有前端代码都是公开的）

需要后端时，换用 Cloudflare Pages、Vercel、Netlify 等服务，或者把这些能力交给 Supabase、Firebase 之类的第三方服务，Pages 继续当静态前端层。

## 发布源怎么选

进入仓库 **Settings → Pages → Build and deployment → Source**，两种模式：

- **Deploy from a branch** — 指定某个分支的某个目录（`/` 或 `/docs`）直接发布。适合纯静态站，本项目用的就是这个。
- **GitHub Actions** — 由工作流构建后再发布。适合需要打包的前端项目。

两种模式不能混用，切换后旧的配置会失效。

## 限制清单

| 项目 | 限制 |
| --- | --- |
| 站点大小 | 1 GB |
| 月带宽 | 约 100 GB（软限制） |
| 构建频率 | 约 10 次 / 小时 |
| 免费账号的私有仓库 | 不能发布 Pages（需 Pro 及以上） |
| 自定义域名 | 一个域名只能绑一个站点 |

## 缓存问题

Pages 走 CDN，改动推送后通常 1 分钟内生效。如果没看到更新，先强制刷新，再等一两分钟。构建状态可以在 **Settings → Pages** 里看到最近一次部署时间。

## 关键配置文件

本仓库根目录的 `.nojekyll` 是**必须存在**的空文件。

原因：Pages 默认会跑 Jekyll 预处理，而 Jekyll 会**忽略所有以下划线开头的文件或目录**。Docsify 的侧边栏文件名恰好是 `_sidebar.md`，一旦被忽略，左侧目录就会整个消失。
